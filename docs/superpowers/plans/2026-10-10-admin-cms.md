# Portfolio Admin CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a private, single-owner CMS at `/admin` that manages the homepage, projects, blog posts, and Cloudinary media while serving published content from Neon without redeployment.

**Architecture:** The Next.js application owns both the public site and protected admin backend. Server-only domain services validate input, execute Drizzle transactions against Neon, write audit/media-usage records, and invalidate narrowly scoped cache tags; public server components consume published repository projections while authenticated draft mode consumes draft projections. Self-managed Better Auth runs from a Node.js route handler with Drizzle-backed users and sessions, and Cloudinary uploads go directly from the browser after a protected signature request.

**Tech Stack:** Next.js 15 App Router, React 18, TypeScript, Bun, Neon Postgres, `pg`, Drizzle ORM/Kit, Better Auth with the Drizzle adapter, CUID2, Zod, Tiptap JSON, Cloudinary, Bun test, and Playwright.

**Spec:** `docs/superpowers/specs/2026-10-10-admin-cms-design.md`

**Authoritative references:** Use the documentation matching the versions locked by Task 1: [Better Auth installation](https://better-auth.com/docs/installation), [Better Auth Drizzle adapter](https://better-auth.com/docs/adapters/drizzle), [Better Auth options](https://better-auth.com/docs/reference/options), [Better Auth rate limiting](https://better-auth.com/docs/concepts/rate-limit), [Drizzle with Neon](https://orm.drizzle.team/docs/tutorials/drizzle-with-neon), [Cloudinary signed browser uploads](https://cloudinary.com/documentation/node_image_and_video_upload), and [Tiptap JSON/HTML utilities](https://tiptap.dev/docs/editor/api/utilities/html).

## Global Constraints

- Keep `neon.ts` on `auth: false`; authentication is self-managed Better Auth on Vercel, not Neon Managed Auth.
- Do not enable the Neon Data API, Object Storage, or a separate API server.
- Use pooled `DATABASE_URL` for application traffic and direct `DATABASE_URL_UNPOOLED` for migrations and administrative scripts.
- Create and use a non-production Neon branch before generating or applying the first migration; rehearse migrations on a branch before production.
- Drizzle schema and committed migrations are the only schema source of truth; do not use ad hoc SQL or `drizzle-kit push` for release work.
- Every database primary key, including Better Auth records, is a CUID2 text value.
- Public signup stays disabled at runtime; only the idempotent command-line bootstrap may create the first administrator.
- Public routes and slugs remain `/`, `/projects`, `/projects/[slug]`, `/blog`, and `/blog/[slug]`.
- Preserve the current no-motion public UI: do not reintroduce GSAP, Lenis, Framer Motion, custom cursors, magnetic controls, entrance reveals, or scroll pinning.
- Preserve existing project and post slugs during import.
- Public reads return published, non-trashed snapshots only; draft reads require a live administrator session even when draft mode is enabled.
- Cache invalidation happens only after a successful transaction.
- Cloudinary folder prefixes are environment-specific and upload API secrets never reach the browser.
- Tests must never use the production Neon branch or production Cloudinary folder.

## Review Focus

- A forged/stale draft-mode cookie must not reveal draft content; Task 11 adds anonymous preview and direct draft-read tests.
- Slug normalization, reserved routes, first-publication immutability, and restore-time collisions must be deterministic; Tasks 2 and 6 pin each case.
- Stale `updatedAt` values from a second tab must return a conflict without changing draft or published data; Tasks 6 and 7 add integration tests.
- Malformed Tiptap trees and unsafe link/image attributes must be rejected before storage or rendering; Task 2 adds allowlist and protocol tests.
- A tampered or orphaned Cloudinary response must not create a trusted asset or hide cleanup failure; Task 8 adds signature, retry, and dependency tests.

## File and Module Map

- `src/env/server.ts`: validates server-only environment variables without exporting secrets to client bundles.
- `src/server/db/client.ts`: shared Node `pg` pool, Vercel pool attachment, Drizzle client, and database types.
- `src/server/db/schema/*.ts`: Better Auth and CMS tables, enums, indexes, and relations.
- `src/domain/content/*.ts`: pure Zod schemas, CUID/slug utilities, rich-text validation, reading-time logic, projections, and action-result types.
- `src/server/auth/*.ts`: Better Auth configuration, server guard, and bootstrap/password-rotation helpers.
- `src/server/content/<domain>/{repository,service}.ts`: database reads plus transaction-owning lifecycle services for each domain.
- `src/server/content/cache.ts`: cache tags and post-commit invalidation mapping.
- `src/app/admin/_actions/*.ts`: thin protected Server Action adapters over parsed service inputs.
- `src/components/admin/**`: admin shell, forms, tables, editor, media picker, status feedback, and confirmation UI.
- `src/components/content/rich-text.tsx`: safe React rendering of validated Tiptap JSON.
- `scripts/*.ts`: explicit migration, admin bootstrap/rotation, and legacy-content seed commands.
- `tests/unit/**`, `tests/integration/**`, `tests/e2e/**`: pure, database-branch, and browser coverage respectively.
